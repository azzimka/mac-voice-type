# Froggy (mac-voice-type) — Документация для агента Кодекс

Данный документ содержит полную историю разработки, архитектурные решения, список решённых проблем и инструкции для дальнейшей поддержки приложения **Froggy**.

---

## 1. Архитектура приложения

- **Платформа**: macOS (нативный Swift, AppKit + SwiftUI).
- **Расположение исходников**: `Sources/Froggy/`.
- **Основной координатор**: [`Sources/Froggy/Core/AppCoordinator.swift`](Sources/Froggy/Core/AppCoordinator.swift).
- **Слушатель горячих клавиш**: [`Sources/Froggy/Core/GlobalHotkeyListener.swift`](Sources/Froggy/Core/GlobalHotkeyListener.swift) (отслеживание нажатий клавиши `Command` через `CGEventTap`).
- **Запись звука**: [`Sources/Froggy/Core/AudioRecorder.swift`](Sources/Froggy/Core/AudioRecorder.swift) (AVAudioEngine + M4A компрессия).
- **Ввод текста**: [`Sources/Froggy/Core/TextInjector.swift`](Sources/Froggy/Core/TextInjector.swift) (прямой ввод Unicode через CoreGraphics).
- **Хранение настроек и ключей**: [`Sources/Froggy/Core/KeychainHelper.swift`](Sources/Froggy/Core/KeychainHelper.swift).
- **Интерфейс оверлея**: [`Sources/Froggy/UI/RecordingOverlayView.swift`](Sources/Froggy/UI/RecordingOverlayView.swift).
- **Сборка**: скрипт [`build_app.sh`](build_app.sh) (собирает `.app` бандл, подписывает `codesign` и генерирует `Froggy.dmg`).

## 2. Режимы работы диктовки

1. **Двойной клик `Command` (2x ⌘)**:
   - **Режим**: Чистый голос → Текст (Whisper).
   - **ИИ**: Языковые модели (LLM) **не используются**.
   - **Логика**: Аудиофайл отправляется на Groq Whisper (`whisper-large-v3-turbo`). Распознанный текст сразу вставляется в активное поле ввода.

2. **Зажатие `Command` (Hold ⌘)**:
   - **Режим**: Голос → Текст → ИИ (Whisper + LLaMA 3.3).
   - **ИИ**: Используется модель Groq для автоматического перевода и коррекции (RU ⇄ EN).
   - **Логика**: Автоматическое определение языка речи и контекстный перевод без ручного переключателя.

## 3. Критические проблемы и как они были решены

### Проблема №1: Конфликт с приложением Reverso и затирание буфера обмена
- **Симптомы**: При окончании диктовки и вставке текста на экране внезапно открывалось окно стороннего переводчика Reverso, а реальный буфер обмена пользователя заменялся надиктованным текстом.
- **Причина**: Текст вставлялся через системный буфер `NSPasteboard.general` с последующей эмуляцией `Cmd+V`. Приложение Reverso имеет фоновый перехватчик `Cmd+C+C` (двойное копирование) с таймером в 500 мс на изменение `changeCount` буфера. Вставка и быстрое восстановление буфера расценивались Reverso как двойное копирование.
- **Решение**: Полный отказ от использования `NSPasteboard`. В [`TextInjector.swift`](Sources/Froggy/Core/TextInjector.swift) реализован метод прямого ввода символов:
  - Фиксация активного приложения (`targetApplication.processIdentifier`) в момент старта диктовки.
  - Генерация прямых событий клавиатуры `CGEvent.postToPid` с передачей UTF-16 Unicode символов (`keyboardEvent(string:)`).
  - Пакетная передача (чанками по 20 символов с задержкой 1.5 мс) для предотвращения проглатывания букв при длинных текстах.
  - **Результат**: Буфер обмена пользователя не затрагивается, Reverso не открывается, текст печатается чисто в любое приложение (TextEdit, Chrome, Telegram, VS Code и т.д.).

### Проблема №2: Хранение Groq API Key
- **Требование**: Не хранить ключ в `.env`-файлах, чтобы скомпилированное приложение `/Applications/Froggy.app` работало автономно без зависимости от папки проекта и терминала.
- **Решение**: Создано хранилище в [`KeychainHelper.swift`](Sources/Froggy/Core/KeychainHelper.swift). Ключ вводится через интерфейс первого запуска (`OnboardingView`), валидируется и сохраняется локально на Mac. Ключ проверен и активен на Groq API.

### Проблема №3: Визуализация звуковой волны (Waveform)
- **Требование**: Реалистичная, высокочувствительная красная звуковая волна в оверлее при речи.
- **Решение**: В оверлее переработана нормализация громкости микрофона (`AudioRecorder.audioLevel`). Добавлен нелинейный логарифмический усилитель с быстрым откликом и естественным затуханием полос, а статичный бейдж «RU ⇄ EN» удалён.

## 4. Правила для агента Кодекс при дальнейшей работе

1. **Не возвращаться к `NSPasteboard`**: Любая вставка текста должна происходить исключительно через прямой ввод символов в [`TextInjector.swift`](Sources/Froggy/Core/TextInjector.swift).
2. **Не трогать логику 2x Command**: В режиме двойного нажатия `Command` не должно быть никаких обращений к LLM-эндпоинтам — только чистый Whisper.
3. **Сборка и проверка**:
   - Для сборки проекта использовать команду:
     ```bash
     ./build_app.sh
     ```
   - Проверять запущенный процесс:
     ```bash
     pgrep -fl Froggy
     ```
4. **Сохранение чистоты Git**: Не коммитить временные бинарники и `.env` файлы. Все изменения должны быть атомарными и протестированными.
